# Interface languages

LightReader ships Simplified Chinese (`zh-CN`) and English (`en`).

- `src/i18n/messages/zh-CN.ts` is the source of truth for message keys.
  `en.ts` is typed as `Messages`, so TypeScript rejects missing or extra keys;
  `src/i18n/i18n.test.ts` also checks that no English message is left empty.
- Components call `useI18n()` and use `t('namespace.key', { param })`.
  Services, errors, and export code call `translate()`, which uses the active
  language set by `AppProviders`.
- Placeholders use `{name}`. Prefer phrasing that avoids plural forms.
- `AppError` messages come from the `errors` namespace by error code.
- Dates and numbers use `formatDate` / `formatNumber` from `useI18n()`.

The language follows the browser/OS preference by default (`zh*` → Chinese,
`en*` → English, otherwise Chinese) and can be fixed in **Settings → Interface
language**. The choice is a per-device UI preference stored in the persisted
app store, and `<html lang>` follows it.

The Chinese catalog is part of the app bundle; the English catalog is loaded on
demand, and the app waits for it before rendering to avoid a flash of Chinese
text.

Not translated on purpose: prompts and tool messages sent to the local model
(they are model input), the bilingual retrieval synonym table, and language
names in the switcher (each shown in its own language).

Tests pin the interface to Chinese (`src/test/setup.ts`,
`playwright.config.ts`); `tests/e2e/i18n.spec.ts` covers English.
