# 本地 AI 模型基线

记录日期：2026-09-08。

## 环境

- Provider：本机 Ollama `http://127.0.0.1:11434`；
- 模型：`deepseek-r1:8b`；
- Ollama 模型 ID：`6995872bfe4c`；
- 本地模型大小：5.2 GB；
- 测试数据：项目自有的一句合成中文说明，不包含用户书籍、笔记或隐私数据。

本基线用于证明 Provider 可用和记录首个行为样本，不是跨设备性能承诺。

## 观察结果

| 场景             | 结果                                                                              |
| ---------------- | --------------------------------------------------------------------------------- |
| 64 token 冷启动  | 总耗时约 5.36 秒；加载约 2.35 秒；模型只返回 `thinking`，正式正文因长度上限被截断 |
| 256 token 热运行 | 总耗时约 10.80 秒；生成 235 token；成功返回一句中文正文                           |
| `think: false`   | 当前模型仍返回独立 `thinking` 字段                                                |

因此生产 Gateway 不转发、不保存也不记录 `thinking`，并为选中文本任务保留
足够的生成预算。用户可能在正式正文出现前经历数秒无可见输出，界面必须显示
明确的“正在生成”状态并始终提供取消按钮。

## 当前门槛

- 固定 60 秒总超时；
- 选中文本最多 12,000 字符；
- 最终正文最多 8,000 字符；
- 思考内容不进入 WebView、SQLite、localStorage、日志或备份；
- 未确认、失败、超时和取消均不能创建 AI 草稿或笔记；
- 真实发布前仍需在目标设备上手动记录首个可见正文延迟和实际取消响应时间。

## 回归建议

模型或 Ollama 版本变化后，使用相同公开测试文本重新记录：服务连接、模型
发现、首个正文延迟、总耗时、空正文比例、取消响应和中文任务质量。不要将
用户书籍正文加入仓库、CI artifact 或托管 trace。
